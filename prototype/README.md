# Meta Ads 全流程本地交互原型

这是 Product Discovery 阶段用于确认产品形态的前端原型。它只使用固定虚构数据，所有
操作只改变浏览器内存状态；没有后端、真实登录、Meta 连接、Cloudflare 资源或外部
写入。

## 启动与检查

需要 Node.js 20 或更高版本：

```bash
npm install
npm run prototype:dev
```

运行原型测试、类型检查和生产构建：

```bash
npm run prototype:check
```

运行仓库全部检查：

```bash
npm run check
```

## SC-01：素材到广告创建与发布状态

1. 从总览打开“素材权利待确认”，进入 `AST-001`。
2. 查看并确认原型素材权利说明。
3. 将素材带入广告创建，选择 `Purchase` 转化事件。
4. 确认发布前检查为 `0 BLOCKER`，进入人工确认。
5. 创建 `PR-001` 待确认请求并推进到模拟发布。
6. 选择模拟审核失败，验证失败原因能返回 `AST-001` 或广告配置。

任何“发布”只推进本地模拟状态，不会向 Meta 发送请求。

## SC-02：投放数据到诊断与行动

1. 从总览或一级导航进入数据分析。
2. 核对账户、日期、时区、归因口径和数据稳定状态。
3. 下钻 Campaign、Ad Set、Ad 和素材。
4. 查看 `DR-004` 的异常、证据、反证、缺失数据和置信度。
5. 保存诊断，并在理解无外部副作用后保存“待确认行动”。

保存建议不会暂停广告、调整预算或改变投放状态。

## SC-03：素材测试到持续优化

1. 打开 `TP-007`，查看假设、控制条件、变体和数据有效性。
2. 保存 `ITERATE` 结论。
3. 确认下一轮只改变一个主要变量。
4. 创建 `TP-008` 草稿，验证状态为“准备中”且不修改现有广告。

## Codex 交接

独立 Codex 会话不嵌入 Web。三个可复现上下文包位于
[Codex 辅助流程](../docs/discovery/codex-prototype/README.md)，分别输出素材与广告配置、
诊断与待确认行动、测试结论与下一轮计划。前期由负责人手动带入 Web 对象。

## 验收证据

- 视觉概念、实现截图、浏览器方法和差异见
  [视觉一致性记录](design/fidelity-ledger.md)。
- 单元测试覆盖可信边界、发布前阻断和诊断“建议未执行”。
- 浏览器已验证三条流程、`1536 × 1024` 桌面布局、`430 × 932` 移动端布局、无页面
  横向溢出和无控制台错误或警告。

这些证据表示原型技术验收完成，不代表项目负责人已经通过 `DG0`，也不证明真实用户
可用性、效率、诊断准确率或广告效果。

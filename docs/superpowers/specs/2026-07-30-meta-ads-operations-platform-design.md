# Meta Ads 全流程运营平台产品设计

## 文档目的

本文定义内部试点产品的产品结构、核心流程和交互边界，综合
[产品定义](../../discovery/product-definition.md)、
[产品形态验证](../../discovery/product-shape-validation.md)和
[证据登记](../../discovery/evidence-log.md)中的负责人决定。

本文不授权业务代码、真实 Meta 接入、Cloudflare 资源、部署或 Meta 写操作。功能分类
只以[产品定义](../../discovery/product-definition.md)中的 `PF-*` 为权威来源。

## 产品结论

产品是面向个人广告主和小团队、覆盖新手到熟练投手的通用 Meta 广告全流程 Web 运营
平台。产品覆盖：

1. 投放前的素材搜索、准备、生成、修改和测试变体。
2. Campaign、Ad Set、Ad 的创建、检查、发布和生命周期管理。
3. 投放中的状态查看、审核失败处理和日常运营。
4. 投放后的数据看板、下钻分析、异常诊断和行动建议。
5. 素材与广告表现关联、持续测试、复盘和知识沉淀。

前期 AI 助手使用独立 Codex 会话，通过项目上下文、信息文档和聚焦 Skills 工作。
Web 前期不内置聊天助手：

- Web 承载业务对象、状态、图表、工作流、操作和审计。
- Codex 承载生成、解释、诊断、建议和文档化辅助。
- 没有受控工具时，Codex 只能处理明确提供的上下文，不能假装读取实时数据。
- 后续 API、MCP 或受控写工具必须经过独立产品、技术和安全评审。

该结论由 `EVD-023` 确认，并由 `EVD-024` 纠正此前“Web 内置助手”和三形态静态故事板
假设。它仍不代表真实用户、市场、可用性、效率或广告效果验证。

## 用户与使用模式

### 支持范围

- 首期支持个人广告主和小团队。
- 同一 Web 产品覆盖新手到熟练投手，不拆分两个产品。
- 新手默认看到引导式流程、术语解释和推荐配置。
- 熟练用户可以切换高级配置、批量选择、详细筛选和对比。
- 代理商、多客户管理和多租户商业化属于后续范围。

### 基础角色

| 角色 | 产品职责 | 不能自动推导的权限 |
| --- | --- | --- |
| `Owner` | 工作区、成员、连接、策略和全局设置 | 未授权的 Meta 写操作 |
| `Editor` | 素材、广告配置、报告、测试计划和待确认动作 | 成员管理或绕过审批 |
| `Viewer` | 查看、筛选和导出授权内容 | 修改对象或触发有副作用操作 |

Codex MUST 使用与用户当前任务一致的角色和数据范围。会话中的自然语言确认不能替代
服务端身份、对象所有权、审批和策略校验。

## 产品信息架构

### 全局上下文

Web 页面 MUST 持续显示：

- 当前工作区和广告账户。
- 数据时间范围、时区、归因口径和数据新鲜度。
- 当前角色、可执行操作和需要审批的操作。
- 全局同步、审核、投放和安全告警。
- 当前对象是否为本地草稿、待确认动作或 Meta 已生效状态。

### 一级导航

| 导航 | 主要内容 | 关联场景 |
| --- | --- | --- |
| 总览 | 待办、异常、投放结果、审核失败、草稿和测试摘要 | SC-01–SC-03 |
| 素材中心 | 搜索、上传、生成、修改、适配、变体、来源、版权和表现 | SC-01、SC-03 |
| 广告创建 | Campaign、Ad Set、Ad 引导式配置、预览、检查和版本 | SC-01 |
| 广告管理 | 发布、审核、投放状态、预算、排期、变更和历史 | SC-01、SC-02 |
| 数据分析 | 指标、趋势、筛选、下钻、异常、诊断和报告 | SC-02 |
| 测试与优化 | 假设、计划、状态、比较、结论和下一轮动作 | SC-03 |
| 设置与治理 | 连接、成员、角色、指标、审批、审计和停止控制 | 全局 |

### 跨模块关系

- 素材必须能查看其关联广告、测试和历史表现。
- Campaign、Ad Set 和 Ad 必须能下钻到素材与数据。
- 诊断建议必须链接证据对象和适用范围。
- 测试结论必须回写为素材表现记录和下一轮计划。
- 审核失败必须链接到需要修改的素材或广告配置。

## 前期 Codex 会话

### 上下文来源

Codex 前期使用：

- 产品需求、广告术语、指标口径、流程规范和安全政策。
- 用户明确提供的商品、素材、配置、脱敏数据或任务文件。
- 为素材、广告创建、分析、优化、报告和变更管理设计的聚焦 Skills。

Codex MUST 在回答中区分：

- 文档中已确认的规则。
- 用户本轮提供的事实。
- 工具返回且带范围和时间的数据。
- 需要验证的推断或建议。

### 输出与交接

Codex 输出 SHOULD 使用可保存的结构：

- 素材简报、文案或视觉变体说明。
- Campaign、Ad Set、Ad 配置草案。
- 指标诊断报告和行动建议。
- 素材测试计划与结论。
- 需要后续审批的结构化变更建议。

前期可以由用户手动把结构化输出带入 Web。后续是否通过 MCP/API 自动保存到 Web 对象
属于技术设计，不得在 Product Discovery 阶段假设已经存在。

### 明确限制

- Codex 没有被提供实时工具时不得声称已读取 Meta。
- Codex 没有被提供受控写工具时不得声称已创建、发布或调整广告。
- Skills 不保存 Token、客户数据或可绕过授权的对象标识。
- Codex 失败时不得丢弃用户输入，必须说明缺少什么以及安全的下一步。

## 核心产品对象

以下为产品概念，不是数据库或 API 契约：

| 对象 | 目的 | 必需可信信息 |
| --- | --- | --- |
| Workspace | 隔离成员、连接和业务对象 | 所有者、成员、角色 |
| Ad Account Context | 指明 Meta 数据与操作范围 | 账户别名、连接、同步、权限 |
| Asset | 保存搜索、上传、改编或生成素材 | 来源、权利、生成标记、规格 |
| Creative Variant | 表达可比较变化 | 基础素材、变化变量、版本 |
| Campaign Draft | 保存 Campaign 配置 | 目标、预算、状态、版本 |
| Ad Set Draft | 保存受众、版位、预算和排期 | 父级、完整度、风险 |
| Ad Draft | 保存素材、文案、落地页和追踪配置 | 父级、预览、完整度 |
| Preflight Report | 汇总发布前风险 | `BLOCKER`、`WARNING`、`INFO` |
| Publish Request | 表达待确认或已授权发布意图 | 审批、payload、过期、状态 |
| Diagnosis Report | 保存异常、证据、假设和建议 | 范围、口径、置信度、执行状态 |
| Test Plan | 保存素材测试假设和控制条件 | 变量、指标、数据条件、停止规则 |
| Test Conclusion | 保存测试结果和下一步 | 证据、干扰因素、可信度 |
| Audit Event | 区分用户、Codex 和系统动作 | 操作者、对象、动作、前后状态 |

## 通用状态与失败体验

对象 SHOULD 使用用户可理解的状态：

- 草稿。
- 需要补充。
- 被阻断。
- 待确认。
- 待审批。
- 发布中。
- 已发布。
- 审核失败。
- 数据不足。
- 数据过期。
- 失败。

未实现或未授权的状态不得伪装成可执行能力。生成、同步、发布或分析失败时，产品 MUST：

1. 保留已有输入、草稿和用户编辑。
2. 说明原因、受影响对象和数据范围。
3. 说明能否安全重试以及是否可能重复执行。
4. 提供下一步和返回入口。
5. 对不支持的 Meta 目标、字段或指标明确标记，不用近似值替代。

## SC-01：从素材准备到广告创建与发布

### 输入

- 商品或服务、投放目标、受众、落地页。
- 已有素材、授权素材搜索需求或 AI 生成需求。
- Campaign、Ad Set、Ad 所需预算、排期、版位和追踪信息。

### SC-01 流程

1. 用户在素材中心搜索允许来源、上传、生成、修改或适配素材。
2. 产品记录来源、版权、AI 生成标记、规格和版本。
3. 用户创建 Campaign、Ad Set 和 Ad；引导模式解释关键配置，高级模式展开完整候选字段。
4. 产品集中预览素材、文案、目标、受众、预算、时间、版位和落地页。
5. 发布前检查按 `BLOCKER`、`WARNING`、`INFO` 展示缺失、冲突、素材、权利和政策风险。
6. 用户保存版本并确认发布意图。
7. 目标产品在具备独立授权和安全控制后提交 Meta；此前提供明确的人工交接且持续显示
   未发布。
8. 审核失败返回具体原因，并链接到需要修改的素材或配置。

### SC-01 完成标准

- 用户能从素材进入完整广告结构，而不是只获得一段文案建议。
- 关键缺失或风险不能被静默绕过。
- 本地草稿、待确认、发布中、已生效和审核失败状态可区分。
- 产品不保证 Meta 审核通过或广告效果。

## SC-02：从投放数据到诊断与行动

### SC-02 流程

1. Web 看板显示账户、对象、时间、时区、归因、指标和数据新鲜度。
2. 用户下钻 Campaign、Ad Set、Ad、素材和允许的其他维度。
3. 异常说明指标、时间、影响范围、比较基线和严重程度。
4. Codex 基于允许使用的上下文排列原因假设，展示证据、反证、缺失数据和置信度。
5. 建议记录动作、适用对象、预期影响、风险、验证周期和停止条件。
6. 结果保存为诊断报告或待确认动作，并与相关广告和素材关联。

### SC-02 完成标准

- 数据过旧、不完整、样本不足、追踪异常或归因延迟时降低置信度或拒绝下结论。
- 不把相关性直接表述为因果。
- 建议、待确认操作和 Meta 已生效状态清楚区分。
- 用户能回答发生了什么、影响哪里、可能为什么、证据是什么和下一步做什么。

## SC-03：从素材变体到持续测试与优化

### SC-03 流程

1. 用户从素材中心或广告对象选择至少两个变体并定义假设。
2. 产品识别变化变量，默认建议一次只测试一个主要变量。
3. 测试计划记录主要指标、保护指标、受众、投放条件、预算、周期、最小数据条件和
   停止规则。
4. Web 显示准备中、数据不足、可评估、无法判断和已结束状态。
5. 产品提示曝光或消耗不均、追踪异常和中途配置变化。
6. Codex 给出 `KEEP`、`STOP`、`ITERATE` 或 `INCONCLUSIVE` 建议及理由。
7. 结论保存到素材和广告对象，形成下一轮可检索依据。

### SC-03 完成标准

- 用户能看清假设、控制变量、证据、可信度和下一步。
- 无法公平比较时必须阻断或标记无效。
- 数据不足或测试失效时返回 `INCONCLUSIVE`。
- 未授权时不得自动暂停、调整预算或修改广告。

## 终端适配

- 桌面端 MUST 支持三个核心场景的完整 Web 流程。
- 移动端 MUST 支持总览、数据查看、异常处理、草稿或报告审核和轻量修改。
- 复杂素材编辑、广告结构配置和批量操作 SHOULD 优先桌面端。
- Codex 会话的终端能力由 Codex 客户端提供，不要求 Web 复制聊天界面。
- 移动端和桌面端 MUST 使用相同权限、状态和安全边界。

## 安全与可信度不变量

- 根目录 [SECURITY.md](../../../SECURITY.md)是安全政策的唯一事实源。
- 当前阶段不得连接真实 Meta 或执行广告写操作。
- 目标写能力必须使用服务端身份、所有权、审批、策略、幂等和审计控制。
- Codex、Skills 和浏览器均不得持有或显示明文 Token。
- 素材必须显示来源、权利状态和生成标记。
- 分析必须显示范围、新鲜度、口径、证据和置信度。
- 审计必须区分用户输入、Codex 输出、人工确认和系统执行。
- 任何未来自动化都必须有预算、对象、操作白名单、停止条件和紧急停止控制。

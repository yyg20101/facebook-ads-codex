# ADR-006：能力只读优先并逐级开放

> 接受依据：`EVD-003`、`EVD-018`、`EVD-019`、`EVD-023`、`EVD-025` 已确认目标产品
> 最终包含受控操作，但内部试点和首期必须先建立可信只读与建议能力。

## 背景

Meta 写操作可能影响预算、投放和客户资产。数据质量、指标口径、权限和审批必须先经过
分阶段验证，不能在文档或代码存在时自动获得写能力。

## 备选方案评审

| 方案 | 结果 | 理由 |
| --- | --- | --- |
| 只读→建议→审批写入→有限自动化 | 采用 | 先验证数据、口径、权限和审计，再逐步扩大副作用。 |
| MVP 同时开放读取和直接写入 | 不采用 | 在真实数据、权限和审批尚未验证时引入预算与资产风险。 |
| 产品永久只读 | 不采用 | 与已确认的全流程目标不一致，但写能力仍须独立 Gate 和授权。 |

## 决策

能力按以下顺序开放：

```text
READ_ONLY
  -> ADVISORY
  -> APPROVAL_REQUIRED
  -> BOUNDED_AUTONOMY
```

不得跳过阶段。生产部署与 Meta 写操作分别需要项目负责人明确授权。

## 后果

- Phase 1–2 可在没有写权限的情况下形成只读 MVP。
- Phase 4 必须同时满足 G2、G3、Meta 管理权限和独立写授权。
- Phase 5 还需要用户批准的 Dry Run、预算、白名单、TTL 和 Emergency stop 测试。

## 风险与可逆性

- 风险：发布和优化闭环会晚于只读分析，但不会用速度换取未经验证的外部副作用。
- 可逆性：阶段顺序本身不可跳过；每一级范围可以通过新需求和 ADR 收窄。进入下一阶段
  必须新增证据和授权，不能以当前 `ACCEPTED` 状态推导。

## 影响

- 关联需求：FR-003、FR-004、FR-010、FR-014、SEC-005、SEC-007、SEC-010。
- Gate：G0–G5 严格按依赖通过，Gate 本身不扩大授权。

# 产品形态与交付界面验证

## 已确认结论

项目负责人确认产品采用两层交付形态：

1. **业务产品主体**是桌面优先、响应式的 Meta 广告 Web 运营平台。
2. **前期 AI 助手入口**是独立 Codex 会话，通过项目上下文、信息文档和聚焦 Skills
   提供生成、解释、诊断、建议与流程辅助。

前期 Web 平台不需要内置聊天助手。Codex 是 AI 交互界面，Web 是业务对象、工作流、
状态和操作的事实界面。两者不能被合并成“聊天窗口主导的产品”。

该决定由 `EVD-023` 支持。`EVD-024` 记录了对旧三形态静态故事板的明确反证，因此
旧 `PROTO-A`、`PROTO-B`、`PROTO-C` 比较不再作为 `DG0` 通过条件。

## 产品目标与当前授权的区别

最终产品范围覆盖素材准备、广告创建与发布、投放管理、数据分析和持续优化。直接创建、
发布或调整 Meta 广告属于目标产品能力，但只有在后续阶段获得独立授权并实现审批、
策略、幂等和审计控制后才能开放。

当前 Product Discovery 的只读模式只限制现在可以执行的动作，不得被解释为最终产品
只能生成草稿或报告。当前阶段仍不得连接真实 Meta、部署或执行任何广告写操作。

## 业务产品主体

Web 运营平台至少包含以下一级产品区域：

| 区域 | 核心职责 | 代表性结果 |
| --- | --- | --- |
| 总览 | 待办、异常、投放状态、数据新鲜度和关键结果 | 可行动的运营首页 |
| 素材中心 | 搜索、上传、生成、修改、适配、变体、来源和表现 | 可复用素材与版本 |
| 广告创建 | 目标、Campaign、Ad Set、Ad、受众、预算、版位和素材配置 | 可检查广告草稿 |
| 广告管理 | 发布状态、审核失败、投放状态、预算和变更记录 | 可控广告生命周期 |
| 数据分析 | 指标、趋势、筛选、下钻、异常和归因上下文 | 可复查诊断报告 |
| 测试与优化 | 素材测试、假设、比较、结论和下一轮动作 | 可复用测试知识 |
| 设置与治理 | 连接、成员、角色、权限、审批和审计 | 明确安全边界 |

Web 平台是业务事实源。无论结果来自用户、Codex 还是后续自动化，业务对象都必须具有
明确状态、来源、时间、权限范围和审计记录。

## 前期 Codex 助手

前期 Codex 会话使用：

- 项目章程、产品需求、指标定义、操作规范和安全边界等上下文文档。
- 广告素材、创建、分析、优化、报告和变更管理等聚焦 Skills。
- 用户明确提供且允许处理的脱敏信息或后续授权工具返回的数据。

前期 Codex 会话 MUST：

- 清楚说明正在使用的上下文、数据范围、新鲜度和限制。
- 将重要输出结构化为可保存的素材说明、广告配置、诊断报告、测试计划或变更建议。
- 在没有受控工具时明确说明无法读取实时数据或执行 Meta 操作。
- 不保存 Token，不把会话确认当作服务端业务授权，不扩大用户角色或数据范围。

Remote MCP、HTTP API、实时数据和受控写工具属于后续技术设计，不能从本产品形态决定
自动推导为已接受架构。

## 不采用的前期形态

| 形态 | 当前结论 | 原因 |
| --- | --- | --- |
| Codex 对话作为完整产品 | 不采用 | 无法独立承载大量广告对象、状态、图表、批量操作和审计 |
| Web 内置聊天作为前期 AI 入口 | 延后 | 前期使用 Codex 会话即可，重复实现聊天入口没有当前价值证据 |
| 只有精简控制台的 Web | 不采用 | 无法覆盖素材、广告创建、投放管理、分析和优化的完整业务流程 |
| Web 运营平台 + 独立 Codex 助手 | 已选 | 业务状态与 AI 推理职责清晰，并能分阶段连接受控工具 |

## 代表性端到端场景

### SC-01：从素材准备到广告创建与发布

- 在素材中心搜索授权来源、上传、生成、修改或适配素材。
- 建立 Campaign、Ad Set 和 Ad 配置，支持引导与高级模式。
- 展示素材权利、字段完整度、预算、受众、版位和政策检查。
- 保存可审核草稿和版本；目标产品在授权后支持人工确认发布。
- 审核失败时回到对应素材或配置问题进行修复并重新提交。

Product Discovery 只验证页面、对象和状态设计；不得执行真实发布。

### SC-02：从投放数据到诊断与行动

- 明确账户、对象、时间、时区、归因和数据新鲜度。
- 在 Web 看板完成趋势、筛选和 Campaign、Ad Set、Ad、素材下钻。
- Codex 根据允许提供的上下文解释异常、证据、反证和置信度。
- 将建议保存为待确认行动或诊断报告，不伪装成已执行变更。

### SC-03：从素材变体到持续测试与优化

- 从素材库或广告对象选择变体并建立测试假设。
- 显示控制变量、主要指标、保护指标、数据条件和停止规则。
- 比较表现并识别样本不足、曝光不均、追踪异常和配置变化。
- 保存 `KEEP`、`STOP`、`ITERATE` 或 `INCONCLUSIVE` 结论及下一轮计划。

## 修正后的验证方法

不再比较三个抽象聊天或工作台壳层。后续验证只针对已选产品形态：

1. 建立完整 Web 信息架构和跨模块对象关系。
2. 制作能连续完成 `SC-01`–`SC-03` 的可交互 Web 产品原型。
3. 单独准备三段 Codex 示例会话，验证上下文文档、Skills、输入限制和结构化输出。
4. 记录负责人能否独立找到入口、完成步骤、识别状态并理解 Web 与 Codex 的分工。
5. 选定形态覆盖至少 80% 的场景关键步骤，且数据、权限、审批和 Meta 写操作关键误解
   为零。

视觉偏好不能覆盖任务失败。无法由低保真原型验证的真实效率、诊断准确率和广告效果必须
延期到具备真实数据与相应授权的阶段。

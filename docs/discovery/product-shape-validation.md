# 产品形态验证

## 前置条件

原型工作只有在至少 3 次有效问题访谈完成、`DQ-02` 与 `DQ-06` 获得初步证据后才能开始。
当前原型和任务状态均为 `NOT_STARTED`，不得使用旧功能清单代替研究结果。

## 可比测试输入

三种形态必须共享：

- 同一组完全脱敏的示例数据。
- 从研究证据选出的 2–3 个核心任务。
- 相同的任务目标、信息完整度和安全限制。
- 相同的完成判定与观察字段。

核心任务在访谈综合后登记：

| Task | 来源问题 | 证据 | 状态 |
| --- | --- | --- | --- |
| TASK-01 | DQ-02、DQ-06 | 待登记 | UNRESOLVED |
| TASK-02 | DQ-02、DQ-06 | 待登记 | UNRESOLVED |
| TASK-03 | DQ-02、DQ-06 | 待登记 | OPTIONAL |

## 三种低保真方案

| Prototype | 形态 | 必须表达的交互 | 状态 |
| --- | --- | --- | --- |
| PROTO-A | Codex 对话式 | 任务发起、澄清、结果、证据和下一步 | NOT_STARTED |
| PROTO-B | Web 工作台式 | 导航、状态、信息层级、操作和反馈 | NOT_STARTED |
| PROTO-C | Codex + Web 混合式 | 对话分析与可视状态/控制之间的交接 | NOT_STARTED |

原型不得连接真实接口、真实账户或未脱敏数据，不得暗示候选写操作已经授权。

## 测试脚本

每名参与者按轮换顺序测试三个方案，避免固定顺序偏差。主持人只说明任务目标，不讲解
界面或推荐方案。每个方案记录：

- 核心任务是否完成及需要的提示次数。
- 完成路径、阻塞、误解和放弃点。
- 能否找到来源、口径、数据时间和限制。
- 能否区分建议、审批和真实外部写操作。
- 对结果的信任理由，而非单纯喜好。
- 相比当前替代方案的实际改善或退步。

## 选择门槛

- 至少 3 名有效参与者完成比较测试。
- 选定形态的关键任务完成率不低于 80%。
- 不得出现对数据可信度、权限或广告写操作的关键误解。
- 选择理由必须同时包含任务表现、问题证据、内容适配和限制。
- 没有方案达到门槛时，结论为 `INCONCLUSIVE`，迭代后重测，`DG0` 保持 `PARTIAL`。

偏好排名可以作为辅助信息，但不能覆盖任务失败或安全误解。

# 数据与迁移规范

> 候选实现规范：Workspace、D1、R2、同步和 migration 尚未选定，`DG0` 前不构成
> 数据实现要求。

## 租户与约束

- 业务表必须直接包含或通过不可绕过的关系解析到 `workspace_id`。
- 唯一约束必须包含 Workspace 作用域和必要的外部版本/口径字段。
- 业务查询从授权上下文注入 Workspace，不能采用客户端提供的自由过滤。
- 外键、检查约束和应用层 schema 共同保护领域不变量。

## 时间、货币和指标

- 存储广告账户时区和原始自然日，不隐式使用 Worker 本地时区。
- 金额同时保留币种；跨币种聚合默认拒绝。
- 归因配置、API 版本、同步批次和稳定状态必须可追溯。
- 指标零分母保存为 `null`，不得将无数据写成零。

## Migration

- 每个 D1 schema 变化使用顺序 migration，不在启动时隐式修改 schema。
- migration 必须说明向前、向后兼容和数据回填影响。
- 破坏性变化优先采用扩展、迁移、切换、清理的分阶段方式。
- 每个 migration 提供回滚或经过验证的前向修复方案。
- migration 测试必须覆盖空库、现有数据、重复执行和失败恢复。

## 幂等与事务

- 同步写入使用稳定逻辑键和 D1 唯一约束。
- 任务状态、批次结果和业务数据更新边界必须明确。
- 不能用“先删后写”掩盖重复或口径变化。
- 外部副作用与数据库状态不能假设跨系统原子；必须使用状态机和可恢复执行记录。

## R2

- 对象 key 包含 Workspace、账户、API 版本、日期和批次等稳定作用域。
- 原始响应与审计快照默认不可变。
- 对象元数据必须脱敏且能关联 D1 记录。
- Token、Header、会话和非必要个人数据不得写入对象。

## 保留与清理

- `BQ-09` 关闭前不得设定生产保留默认值。
- 清理任务必须区分原始数据、标准化指标、导出、审计和变更快照。
- 删除必须经过授权、可审计，并保留法律或安全要求的必要证据。

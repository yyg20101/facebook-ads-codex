# Facebook Ads 通用投放与分析助手产品设计

## 文档目的

本文定义内部试点产品的交互与内容设计，综合
[产品定义](../../discovery/product-definition.md)、
[产品形态验证](../../discovery/product-shape-validation.md)和
[证据登记](../../discovery/evidence-log.md)中的负责人决定。

本文不授权业务实现、真实 Meta 接入、Cloudflare 资源创建、部署或 Meta 写操作。
`PF-*` 分类只以[产品定义](../../discovery/product-definition.md)为权威来源；本文负责说明
这些能力如何组成一致的产品体验。

## 产品结论

产品是面向个人广告主和小团队的通用 Meta 广告投放与数据分析助手，覆盖新手到熟练
投手。MVP 使用桌面优先的响应式 Web 工作台，并内置上下文对话助手：

- 工作台承载对象、状态、数据、证据和明确控制。
- 助手承载素材生成、配置解释、异常诊断和行动建议。
- 助手结果必须保存为可浏览和可检查的工作台对象，不能只存在于聊天历史。
- MVP 只生成素材、草稿、报告和建议，用户在产品外手动完成 Meta 发布或修改。

该结论只代表项目负责人确认的内部试点产品定义，不代表已验证真实用户需求、外部市场、
可用性、节省时间或广告效果。

## 问题与价值

### 问题假设

候选用户需要在 Meta Ads Manager、素材或 AI 工具、表格或报表及沟通文档之间切换，
导致素材决策、广告配置、数据结论和测试知识彼此割裂：

- 新手难以理解配置、指标和风险。
- 熟练投手仍需重复整理素材、配置、数据和复盘记录。
- 分析结论容易缺少统一口径、证据、置信度和复查条件。
- 素材测试经验难以沉淀到下一次投放。

以上是负责人确认的产品假设，不是用户研究结论。实际频率、严重程度和业务影响按
`DQ-02`、`DQ-04` 延后到真实试点任务或遥测数据阶段验证。

### 价值主张

产品 MUST 在一个保留人工控制的可信工作台中：

1. 把目标简报转为信息完整、风险可见的广告草稿。
2. 把只读投放数据转为带证据、置信度和复查条件的行动建议。
3. 把素材变体转为带假设、控制条件和结论的可复用测试知识。

MVP MUST NOT 保证广告效果或 Meta 审核通过，也 MUST NOT 把建议描述为已经执行。

## 用户与权限

### 支持范围

- MVP 支持个人广告主和小团队中的新手到熟练投手。
- 默认引导模式解释术语并逐步收集必要信息。
- 高级模式展开完整候选配置、筛选和比较能力。
- 最终产品 MAY 扩展至代理商和多客户隔离，但不属于 MVP。

### 基础角色

| 角色 | 允许的产品职责 | MVP 禁止事项 |
| --- | --- | --- |
| `Owner` | 管理工作区、成员、广告账户连接和全局设置 | 通过产品发布或修改 Meta 广告 |
| `Editor` | 创建和编辑素材、草稿、诊断报告及测试计划 | 管理成员、账户连接或执行 Meta 写操作 |
| `Viewer` | 只读查看和导出被授权的内容 | 修改对象、触发 AI 生成或执行 Meta 写操作 |

内置助手 MUST 继承当前用户的角色、工作区和数据范围，MUST NOT 扩大权限或跨工作区
读取信息。

## 产品形态决策

### 已选方案

选择“Web 工作台 + 内置对话助手”：

- 结构化页面适合浏览素材、草稿、指标、测试状态和审计信息。
- 对话适合开放式生成、术语解释、诊断推理和下一步建议。
- 对话结果落入结构化对象，避免关键内容被会话历史淹没。

### 未选方案

| 方案 | 优点 | 不作为主形态的原因 |
| --- | --- | --- |
| 对话主导 | 入门自然，适合澄清和解释 | 大量对象、状态、指标和批量比较容易被会话淹没 |
| 纯 Web 工作台 | 状态、筛选和可控操作清楚 | 创作、解释和开放式诊断容易变成复杂表单 |
| 混合工作台 | 同时支持状态控制和解释型任务 | 实现和交互更复杂，必须严格定义工作台与助手的交接 |

该选择来自 `EVD-013` 和 `SC-01`–`SC-03` 的负责人流程评审；尚未完成真实用户
可用性测试。

## 信息架构

### 全局区域

产品 MUST 持续显示：

- 当前工作区和广告账户。
- 当前数据时间范围、时区和数据新鲜度。
- 当前用户角色和操作权限。
- 当前引导或高级模式。
- 影响结果可信度的全局告警。

### 主导航

| 导航 | 主要内容 | 关联场景 |
| --- | --- | --- |
| 总览 | 待处理任务、关键状态、异常、草稿和测试摘要 | SC-01–SC-03 |
| 素材 | 素材、文案、图片变体、来源、版权和表现记录 | SC-01、SC-03 |
| 广告草稿 | 引导式配置、结构化草稿、版本和发布前检查 | SC-01 |
| 数据分析 | 指标、趋势、筛选、异常、诊断和行动建议 | SC-02 |
| 素材测试 | 假设、计划、状态、结果和下一轮建议 | SC-03 |

### 内置助手

- 桌面端 SHOULD 使用可收起的上下文侧栏。
- 移动端 SHOULD 使用抽屉或独立对话视图。
- 助手 MUST 明确当前使用的页面、对象和数据范围。
- 助手生成的素材、草稿、诊断或测试建议 MUST 要求用户保存或确认到对应对象。
- 助手 MUST NOT 仅用自然语言暗示外部操作已经发生。

## 核心产品对象

以下是产品概念，不是数据库或 API 契约：

| 对象 | 目的 | 关键可信信息 |
| --- | --- | --- |
| Workspace | 隔离成员、连接和产品对象 | 所有者、成员、角色 |
| Ad Account Context | 指明候选 Meta 数据范围 | 账户别名、连接状态、同步时间、权限 |
| Asset | 保存上传、改编或生成素材 | 来源、版权、生成标记、规格 |
| Creative Variant | 表达可比较的素材或文案变化 | 基础素材、变化变量、版本 |
| Ad Draft | 保存结构化广告配置 | 完整度、版本、未发布状态 |
| Preflight Report | 汇总草稿发布前风险 | `BLOCKER`、`WARNING`、`INFO` |
| Diagnosis Report | 保存异常、证据、假设和建议 | 范围、口径、置信度、未执行状态 |
| Test Plan | 保存素材测试假设与控制条件 | 变量、指标、数据条件、停止规则 |
| Test Conclusion | 保存测试结果和下一步 | 证据、干扰因素、结论可信度 |
| Audit Event | 区分人工与助手行为 | 操作者、时间、对象、动作、前后状态 |

## 通用状态与失败体验

对象 SHOULD 使用用户可理解的状态，例如：

- 草稿。
- 需要补充。
- 被阻断。
- 待审核。
- 数据不足。
- 数据过期。
- 失败。

生成、同步或分析失败时，产品 MUST：

1. 保留已有输入、草稿和用户编辑。
2. 说明失败原因及受影响对象或数据范围。
3. 说明能否安全重试以及重试是否可能产生重复结果。
4. 提供下一步，而不是返回不可行动的通用错误。
5. 对不支持的 Meta 目标、字段或指标显式标记，MUST NOT 用近似值替代。

## SC-01：从目标简报到可审核广告草稿

### SC-01 输入

- 商品或服务。
- 投放目标。
- 受众。
- 落地页。
- 已有素材或素材生成要求。

缺失信息 MUST 显式标记，助手 MUST NOT 擅自补齐关键配置。

### SC-01 流程

1. 用户提交目标简报并选择上传、改编或生成素材。
2. 素材和变体记录来源、版权状态和 AI 生成标记。
3. 引导模式收集必要配置并解释影响；高级模式展开完整候选字段。
4. 工作台生成结构化草稿，集中预览素材、文案、目标、受众、预算和时间。
5. 发布前检查以 `BLOCKER`、`WARNING`、`INFO` 展示缺失字段、配置冲突、素材规格、
   版权和 Meta 政策风险。
6. 用户保存草稿版本、检查结果和发布清单，并在产品外手动发布。

### SC-01 完成标准

- 草稿信息完整度和关键缺失可见。
- 素材来源和权利状态可追踪。
- 任何阻断问题不能被静默绕过。
- 界面持续显示广告尚未通过产品发布。
- 检查结果不得承诺 Meta 一定通过审核。

## SC-02：从只读数据到诊断与行动建议

### SC-02 输入

- 广告账户和对象范围。
- 时间区间和比较基线。
- 数据更新时间和时区。
- 归因口径和指标定义。

### SC-02 流程

1. 看板按投放目标显示核心指标、趋势和分层结果。
2. 用户下钻至可用的 Campaign、Ad Set、Ad、素材或其他维度。
3. 异常说明异常指标、发生时间、影响范围、比较基线和严重程度。
4. 助手按置信度排列原因假设，同时展示支持证据、反证、缺失数据和其他解释。
5. 建议记录动作、适用对象、预期影响、风险、验证周期和停止条件。
6. 诊断保存为可复查报告，并关联相关广告、素材和测试记录。

### SC-02 降级与完成标准

- 数据过旧、不完整、样本不足、追踪异常或归因延迟时，产品 MUST 降低置信度或拒绝
  下结论。
- 产品 MUST NOT 把相关性直接表述为因果。
- 建议 MUST 标记为尚未执行。
- 用户必须能够回答发生了什么、影响哪里、可能为什么、证据是什么、下一步做什么和
  何时复查。

## SC-03：从素材变体到测试结论

### SC-03 输入

- 至少 2 个素材或文案变体。
- 明确的测试假设。
- 候选投放条件和比较约束。

### SC-03 流程

1. 系统识别图片、文案、受众、版位等变化，默认建议一次只测试一个主要变量。
2. 测试计划记录主要指标、保护指标、受众与投放条件、预算与周期、最小数据条件、
   复查时间和停止规则。
3. 工作台显示准备中、数据不足、可评估、无法判断或已结束。
4. 产品提示曝光或消耗不均、追踪异常和中途配置变化。
5. 比较结果展示数据范围、指标口径、差异、置信度和干扰因素。
6. 助手给出 `KEEP`、`STOP`、`ITERATE` 或 `INCONCLUSIVE` 建议。
7. 结论保存到对应素材，形成可检索的表现记录。

### SC-03 完成标准

- 用户能看清测试假设、控制变量、证据、结论可信度和下一步。
- 无法公平比较时 MUST 阻断或标记无效。
- 数据不足或测试失效时 MUST 返回 `INCONCLUSIVE`。
- MVP MUST NOT 自动暂停、调整或修改 Meta 广告。

## MVP 功能边界

### MVP

MVP 由[产品定义中的 `PF-001`–`PF-010`](../../discovery/product-definition.md#功能决策)
组成：

- 混合工作台、引导或高级模式和上下文助手。
- 个人与小团队工作区及基础角色。
- 素材管理、适配、AI 文案与图片变体和权利标记。
- 广告草稿、版本、发布前检查和人工发布清单。
- 只读数据看板、异常诊断、行动建议和报告。
- 素材测试计划、比较、结论和表现记录。
- 基础审计。

### LATER

- 经独立授权和逐对象审批的 Meta 发布或修改。
- 有预算、白名单和熔断边界的有限自动优化。
- 全部投放目标和高级广告配置。
- 授权素材搜索、视频编辑和 AI 视频。
- 代理商、多客户管理和隔离。
- 预测、复杂归因、跨账户比较和高级模型。

### REJECTED

- 未经明确批准的广告、预算或投放状态修改。
- 来源或商业授权不明的网络素材。
- 保证广告效果或保证 Meta 审核通过。
- 猜测关键配置、制造测试赢家或把相关性描述为因果。

## 终端适配

- 桌面端 MUST 支持三个核心场景的完整流程。
- 移动端 MUST 支持总览、数据查看、诊断、助手对话、草稿或报告审核和轻量修改。
- 复杂素材编辑和高级配置 SHOULD 引导用户使用桌面端，但不能隐藏其当前状态和限制。
- 移动端和桌面端 MUST 使用相同权限、可信信息和未发布边界。

## 安全与可信度不变量

- 根目录 [SECURITY.md](../../../SECURITY.md)是安全政策的唯一事实源。
- MVP MUST NOT 提供 Meta 写操作。
- 助手 MUST NOT 扩大当前用户的数据范围或权限。
- 素材 MUST 显示来源、版权状态和生成标记。
- 分析 MUST 显示范围、新鲜度、口径、证据和置信度。
- 审计 MUST 区分人工编辑、助手生成和人工确认。
- Token、Secret、客户数据、未脱敏生产响应或个人信息 MUST NOT 进入仓库或产品示例。
- 任何未来写能力都需要新的项目授权、产品评审、安全设计和实施 Gate。

## 设计验收

当前验收只检查负责人确认的设计是否覆盖三个场景，不代表真实用户任务完成率：

| 场景 | 关键步骤 | 已覆盖 | 设计覆盖率 | 关键边界 |
| --- | ---: | ---: | ---: | --- |
| SC-01 | 6 | 6 | 100% | 关键缺失不可静默绕过，始终未发布 |
| SC-02 | 6 | 6 | 100% | 数据不足降级，建议未执行，不伪造因果 |
| SC-03 | 7 | 7 | 100% | 测试无效返回 `INCONCLUSIVE`，不自动修改广告 |

设计覆盖率达到负责人设定的 80% 门槛，且文档明确表达数据、权限和 Meta 写操作边界。
以下指标仍未验证：

- 真实用户任务完成率。
- 真实节省时间。
- 诊断准确率。
- 广告效果提升。
- 外部客户或市场有效性。

## DG0 前的剩余验证

正式评估 `DG0` 前 MUST：

1. 对本文与 Discovery 事实源执行一致性和链接自审。
2. 使用相同脱敏输入制作对话式、纯 Web 和混合工作台三种低保真方案。
3. 由项目负责人分别使用 `SC-01`–`SC-03` 完成同任务走查，记录完成步骤和理解偏差。
4. 验证选定形态的任务完成率不低于 80%，且数据、权限和 Meta 写操作关键误解为零。
5. 确认 `DQ-07`、`DQ-08` 的关闭证据和限制准确。
6. 由项目负责人审阅本文最终版本。
7. 将无法由文档验证的真实用户可用性和广告效果明确延期，不能误报为通过。

# Meta Ads 全流程本地交互原型

这是 Product Discovery 阶段用于确认产品形态的前端原型。大部分操作只改变浏览器内存
状态；数据分析页还可通过固定 Vite 开发代理读取本机 fixture Worker。两者都只使用固定
虚构数据，没有真实登录、Meta 连接、Cloudflare 远程资源或外部写入。

## 启动与检查

需要 Node.js 20 或更高版本：

```bash
npm install
npm run prototype:dev
```

需要验证数据分析的本地端到端链路时，先初始化 fixture D1，并在两个终端分别启动
Worker 和原型：

```bash
npm run worker:db:migrate:local
npm run worker:db:seed:local
npm run worker:dev:web
```

```bash
npm run prototype:dev
```

打开数据分析页，点击“读取 fixture 账户”，从 Worker 返回列表选择账户。先在“步骤 2”
设置 3–31 日范围并运行离线数据质量 preflight；只有账户与全部对象的粒度、覆盖、
上下文、层级和三层逐日汇总全部通过，指标分析入口才会解锁。随后读取对象层级并选择
Campaign；可点击“加载直接子对象拆解”查看直接 Ad Set 的两期变化与父子对账，也可
分别点击“加载所选对象对比”或“加载所选账户对比”。选择 Ad 时拆解入口禁用。选择任一
对象后还可加载 3–31 日趋势；页面一次展示固定 9 项指标中的一项，切换指标不重新请求，
并同时显示图表与精确日值。Campaign 或 Ad Set 还可加载直接子对象趋势，用父对象参考线
和稳定 ID 子对象序列逐日对账；Ad 入口禁用。所有分析日期必须位于 preflight 覆盖范围，
响应口径和快照必须匹配；否则入口重新锁定或结果被拒绝。页面不评价表现、不排名或解释
趋势。成功 comparison 还会派生一个只读 JSON，供负责人手动带入独立 Codex 会话；
该输入不保存、不上传，也不生成分析结论或建议。质量通过和证据包都不作为 Gate 证据。
浏览器只请求同源 `/offline-api/`，
Vite 将其固定代理到 `127.0.0.1:8791`；生产构建关闭该入口。验证后停止两个进程。

运行原型测试、类型检查和生产构建：

```bash
npm run prototype:check
```

运行仓库全部检查：

```bash
npm run check
```

## 页面范围

| 路径 | 产品区域 | 主要内容 |
| --- | --- | --- |
| `/overview` | 总览 | 指标、趋势、待办、广告对象和素材表现 |
| `/assets` | 素材中心 | 来源、权利、规格、版本、变体和关联对象 |
| `/create` | 广告创建 | Campaign、Ad Set、Ad、预览和发布前检查 |
| `/manage` | 广告管理 | 广告状态、模拟发布、审核失败和修复回链 |
| `/analytics` | 数据分析 | 本地 fixture 周期对比、范围、下钻、诊断、证据、反证和待确认行动 |
| `/testing` | 测试与优化 | 测试计划、有效性、对比、结论和下一轮草稿 |
| `/governance` | 设置与治理 | 角色、连接、审批边界和原型审计 |

## SC-01：素材到广告创建与发布状态

1. 从总览打开“素材权利待确认”，进入 `AST-001`。
2. 查看并确认原型素材权利说明。
3. 将素材带入广告创建，选择 `Purchase` 转化事件。
4. 确认发布前检查为 `0 BLOCKER`，进入人工确认。
5. 创建 `PR-001` 待确认请求并推进到模拟发布。
6. 选择模拟审核失败，验证失败原因能返回 `AST-001` 或广告配置。

任何“发布”只推进本地模拟状态，不会向 Meta 发送请求。

## SC-02：投放数据到诊断与行动

1. 从总览或一级导航进入数据分析。
2. 在本地 Worker 已启动时读取 fixture 账户列表，只从返回列表选择账户，再加载预设
   上下文。
3. 对覆盖后续分析周期的 3–31 日范围运行数据质量 preflight，确认 7/7 项检查为
   `PASS`；此前所有指标入口必须锁定，超出覆盖范围后必须重新锁定。
4. 读取所选账户的 fixture 对象层级，选择 Campaign、Ad Set 或 Ad，并确认页面仍标注
   当前对象与父级。
5. 对 Campaign 或 Ad Set 显式加载直接子对象拆解，核对父子级别、两期四项可加指标
   对账和“无排名 · 无阈值 · 非因果”边界；Ad 不提供伪子级。
6. 对当前对象显式加载三日趋势，切换一项指标并核对图表、日值表、完整覆盖和“不解释
   趋势”边界；指标切换不得触发新请求。
7. 对 Campaign 或 Ad Set 显式加载直接子对象日趋势，核对稳定 ID 顺序、父对象参考线、
   每日四项可加指标对账和“无排名”边界；切换指标不得触发新请求，Ad 入口必须禁用。
8. 显式加载所选对象对比，核对对象范围、账户引用、日期、币种、时区、归因口径、完整
   覆盖和数据稳定状态；必要时另行加载账户级结果，并确认响应快照与 preflight 一致。
9. 查看 fixture 指标变化和确定性诊断，再区分下方 Product Discovery 静态流程内容。
10. 查看“Codex 手动上下文”只读 JSON，确认其标记 `FIXTURE`、preflight `PASS`、
    `FACT` / `UNKNOWN`、`recommendations_generated: false` 和 `external_write: false`；
    编辑日期后旧 JSON 必须立即消失。
11. 下钻静态故事中的 Campaign、Ad Set、Ad 和素材。
12. 查看 `DR-004` 的异常、证据、反证、缺失数据和置信度。
13. 保存诊断，并在理解无外部副作用后保存“待确认行动”。

加载或保存建议不会暂停广告、调整预算或改变投放状态。fixture 诊断只确认数字模式，
不代表原因已确定。

## SC-03：素材测试到持续优化

1. 打开 `TP-007`，查看假设、控制条件、变体和数据有效性。
2. 保存 `ITERATE` 结论。
3. 确认下一轮只改变一个主要变量。
4. 创建 `TP-008` 草稿，验证状态为“准备中”且不修改现有广告。

## Codex 交接

独立 Codex 会话不嵌入 Web。三个可复现上下文包位于
[Codex 辅助流程](../docs/discovery/codex-prototype/README.md)，分别输出素材与广告配置、
诊断与待确认行动、测试结论与下一轮计划。前期由负责人手动带入 Web 对象。数据分析页
新增的[离线证据包](../docs/technical/offline-codex-evidence-bundle.md)方向相反：它只把
当前 preflight 支持的 fixture 事实作为手动 Codex 输入，不是 Skill 分析输出。
[趋势扩展](../docs/technical/offline-codex-trend-evidence.md)还可传递对象或直接子对象的
完整固定 9 项日值；当前图表指标不会改变 JSON，序列也不构成解释或排名。

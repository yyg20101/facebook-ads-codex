# 用户研究计划

## 研究目标

在不展示既有解决方案的前提下，确认内部用户近期真实执行的 Meta 广告任务、当前流程、
重复成本、风险、期望结果和最小信息需求，为产品形态和 MVP 决策提供证据。

## 参与者

- 目标样本：3–5 名内部真实用户。
- 有效下限：3 名；少于 3 名时 `DG0` 不得为 `PASS`。
- 优先覆盖不同职责、Meta 广告经验和工作频率。
- 参与者必须在近期实际执行或直接负责相关任务，纯旁观者不计入有效样本。
- 使用 `P-01`–`P-05` 别名，不在仓库记录身份映射。

项目负责人负责招募、知情说明、安排和身份映射。Codex 只处理用户主动提供的脱敏材料，
不联系参与者，也不访问日历、邮件、聊天或会议系统。

## 研究顺序

1. 准备：确认参与者符合条件，建立空白证据记录。
2. 问题访谈：使用[访谈指南](interview-guide.md)，不展示候选方案。
3. 单次综合：每场后只记录事实、推断、反证和待追问，不提前选形态。
4. 跨访谈综合：识别重复任务、成本、差异和无共识项。
5. 原型准备：仅根据已记录的高优先任务构造三种可比方案。
6. 任务测试：使用[产品形态验证](product-shape-validation.md)统一测试。
7. 决策：更新 `DQ-*`、产品定义和 `DG0`，由项目负责人评审。

## 访谈质量

每名有效参与者至少提供：

- 一项最近 30 天内发生的具体任务。
- 实际触发条件、操作步骤、使用工具和协作对象。
- 耗时、返工、错误、等待或决策困难的具体实例。
- 当前替代方案及其仍被使用的原因。
- 对结果可信度、权限和人工控制的实际要求。

只表达喜好、未来愿望或对候选功能的赞同，不构成问题证据。

## 证据与隐私

- 仓库只保存[证据登记](evidence-log.md)中的脱敏摘要。
- 原始录音、视频、逐字稿、姓名、邮箱、电话、聊天记录和客户数据不得入库。
- 每项研究推断必须区分 `FACT`、`INFERENCE`、`COUNTEREVIDENCE`。
- 证据冲突必须保留，不能通过删除反例制造共识。

## 停止与升级条件

出现以下情况时暂停综合并报告：

- 无法获得至少 3 名有效参与者。
- 参与者没有近期相关任务，只能讨论假设。
- 研究材料包含无法安全脱敏的客户或个人数据。
- 候选问题之间没有重复模式，无法选择一个内部试点方向。
- 需要接触外部用户、真实 Meta 账户或其他未授权资源。

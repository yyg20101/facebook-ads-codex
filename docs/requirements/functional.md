# 功能需求

以下条目已按[产品定义](../discovery/product-definition.md)中的 `PF-*` 和 Phase 0 已确认
事实重新评审。`ACCEPTED` 只确认需求语义和后续验收约束，不表示功能已经实现、G0 已
通过或获得真实 Meta/Cloudflare、部署和写操作授权。`DRAFT` 条目继续等待产品优先级、
真实环境事实或后续写能力 Gate。

## FR-001：列出授权工作空间和广告账户

- 状态：`ACCEPTED`
- 候选阶段：Phase 2
- 依赖：`DQ-01`、`DQ-07`、`BQ-01`、`BQ-02`、`BQ-11`
- 产品映射：`PF-002`、`PF-007`；证据 `EVD-006`、`EVD-019`、`EVD-023`
- 要求：系统 MUST 只返回认证用户有权访问的 Workspace 和 Meta Ad Account。
- 验收：跨 Workspace 或伪造对象 ID 的请求被拒绝，响应包含数据新鲜度。

## FR-002：同步广告对象层级

- 状态：`ACCEPTED`
- 候选阶段：Phase 1
- 依赖：`DQ-06`、`DQ-07`、`BQ-01`
- 产品映射：`PF-005`、`PF-007`；证据 `EVD-015`、`EVD-016`、`EVD-023`
- 要求：系统 MUST 同步 Ad Account、Campaign、Ad Set 和 Ad 及其层级关系。
- 验收：对象可追溯到 Workspace、连接和父级；缺失父级会触发质量告警。

## FR-003：保存日粒度 Insights

- 状态：`ACCEPTED`
- 候选阶段：Phase 1
- 依赖：`DQ-06`、`BQ-03`–`BQ-08`
- 产品映射：`PF-007`、`PF-008`、`PF-009`；证据 `EVD-016`、`EVD-017`、`EVD-023`
- 要求：系统 MUST 保存账户、Campaign、Ad Set 和 Ad 的日粒度指标及口径上下文。
- 验收：重复同步不会生成重复逻辑行，每行可追溯至 `sync_run_id`。

## FR-004：公开数据状态

- 状态：`ACCEPTED`
- 候选阶段：Phase 1–2
- 依赖：`DQ-06`、`DQ-08`、`BQ-03`–`BQ-08`
- 产品映射：`PF-007`、`PF-008`；证据 `EVD-016`、`EVD-019`、`EVD-021`、`EVD-023`
- 要求：Web 以及后续启用的 API 或 Codex 工具界面 MUST 显示同步时间、错误、实际覆盖
  截止时间和稳定状态。
- 验收：数据过期或同步失败时，Codex 不输出无警告的确定性业务结论。

## FR-005：执行周期对比与驱动诊断

- 状态：`ACCEPTED`
- 候选阶段：Phase 2
- 依赖：`DQ-02`、`DQ-05`、`DQ-06`、`BQ-03`–`BQ-08`
- 产品映射：`PF-008`、`PF-021`；证据 `EVD-009`、`EVD-016`、`EVD-023`、`EVD-025`
- 要求：Codex MUST 能按账户、Campaign、Ad Set 和 Ad 分解 KPI 变化。
- 验收：结果包含范围、口径、证据、驱动分解、置信度和下一步检查。

## FR-006：生成每日简报

- 状态：`DRAFT`
- 候选阶段：Phase 2
- 依赖：`DQ-02`、`DQ-06`
- 产品映射：`PF-008` 的候选呈现；`EVD-009`、`EVD-016` 尚未确认每日生成的必要性、
  触发方式和“实质变化”判定依据
- 要求：系统 MUST 能生成只报告实质变化的每日简报。
- 验收：无重要变化时明确输出“无须处理”；数据异常优先于优化建议。

## FR-007：生成有证据的优化建议

- 状态：`ACCEPTED`
- 候选阶段：Phase 2
- 依赖：`DQ-05`、`DQ-08`、`BQ-03`–`BQ-08`
- 产品映射：`PF-008`、`PF-009`；证据 `EVD-016`–`EVD-018`
- 要求：每项建议 MUST 包含目标、事实、动作、影响方向、风险、反证条件和证据。
- 验收：数据量或口径不足时只建议继续观察或收集数据，不把相关性表述为因果。

## FR-008：创建内部变更申请

- 状态：`DRAFT`
- 候选阶段：Phase 4
- 依赖：`DQ-07`、`DQ-08`、`BQ-10`
- 产品映射：`PF-011`（`LATER`）；证据 `EVD-003`、`EVD-023`
- 要求：Codex MAY 草拟并提交结构化内部变更申请，但 MUST NOT 直接生成任意 Meta 写请求。
- 验收：申请包含目标、schema 校验后的 patch、理由和证据，不产生外部副作用。

## FR-009：网页审批变更

- 状态：`DRAFT`
- 候选阶段：Phase 4
- 依赖：`DQ-07`、`DQ-08`、`BQ-10`
- 产品映射：`PF-011`（`LATER`）；证据 `EVD-003`、`EVD-019`、`EVD-023`
- 要求：批准和拒绝 MUST 由具备权限的用户在 Web 运营平台完成。
- 验收：Codex 工具确认不能替代网页审批；审批身份、时间和决定写入审计。

## FR-010：执行已批准变更

- 状态：`DRAFT`
- 候选阶段：Phase 4
- 依赖：`DQ-07`、`DQ-08`、`BQ-10`
- 产品映射：`PF-011`（`LATER`）；证据 `EVD-003`、`EVD-019`、`EVD-023`
- 要求：外部写工具只能接受 `change_request_id`，并加载已批准的不可变 payload。
- 验收：未批准、过期、状态变化、策略失败或重复的请求不能产生外部写入。

## FR-011：提供 Web 运营平台

- 状态：`ACCEPTED`
- 候选阶段：Phase 3–4
- 依赖：`DQ-06`、`DQ-07`、`DQ-08`、`BQ-11`
- 产品映射：`PF-001`；证据 `EVD-021`、`EVD-023`、`EVD-025`
- 要求：Web MUST 支持首期总览、素材、广告草稿与状态、数据分析、测试与优化、账户
  上下文和审计；未授权的发布、审批或写操作 MUST 清晰禁用并解释原因。
- 验收：三个核心场景可跨模块完成；网页不显示 Token、不直连 Meta API，用户只能看到
  授权 Workspace，且禁用能力不会伪装为已连接或可执行。

## FR-012：独立执行后台任务

- 状态：`ACCEPTED`
- 候选阶段：Phase 1
- 依赖：`DQ-06`、`DQ-08`、`BQ-08`
- 产品映射：`PF-007`、`PF-010`；证据 `EVD-016`、`EVD-019`、`EVD-023`
- 要求：同步、回补、健康检查、重试和数据稳定更新 MUST 独立于 Codex 客户端。
- 验收：Codex 离线时后台任务仍按计划执行并记录状态。

## FR-013：记录安全审计事件

- 状态：`ACCEPTED`
- 候选阶段：Phase 1–4
- 依赖：`DQ-08`、`BQ-09`、`BQ-10`
- 产品映射：`PF-010`；证据 `EVD-019`、`EVD-023`
- 要求：认证、连接、同步、建议、审批、执行和 Emergency stop 变化 MUST 产生脱敏审计事件。
- 验收：事件包含 actor、target、request、时间和脱敏元数据，普通业务流程不能修改。

## FR-014：按阶段开放能力

- 状态：`ACCEPTED`
- 候选阶段：全部
- 依赖：`DQ-08`、`BQ-10`
- 产品映射：`PF-006`、`PF-011`、`PF-012`；证据 `EVD-003`、`EVD-018`、
  `EVD-019`、`EVD-023`
- 要求：能力 MUST 按 `READ_ONLY -> ADVISORY -> APPROVAL_REQUIRED -> BOUNDED_AUTONOMY` 开放。
- 验收：任何 Gate 或实现都不能绕过独立的生产部署和 Meta 写授权。

## FR-015：生成原始快照和导出

- 状态：`ACCEPTED`
- 候选阶段：Phase 1+
- 依赖：`DQ-06`、`BQ-09`
- 产品映射：`PF-007`、`PF-010`；证据 `EVD-019`、`EVD-023`
- 要求：系统 SHOULD 保存脱敏的不可变原始响应和按需生成导出。
- 验收：原始响应保留 90 天，临时导出保留 30 天；到期清理和连接撤销后的加速删除
  符合[分层保留政策](../technical/domain-and-data.md#保留与删除)，导出访问仍须经过授权。

## FR-016：接入外部转化数据

- 状态：`DRAFT`
- 候选阶段：Post-MVP
- 依赖：`DQ-06`、`BQ-05`
- 产品映射：首期明确排除的候选扩展；证据 `EVD-009`、`EVD-018`
- 要求：系统 MAY 接入 Pixel、Conversions API、CRM 或线下转化数据。
- 验收：数据源、身份匹配、隐私、保留期和指标影响必须先形成独立需求。

## FR-017：管理素材及其权利来源

- 状态：`ACCEPTED`
- 候选阶段：Phase 3
- 依赖：`DQ-05`、`DQ-06`、`DQ-08`
- 产品映射：`PF-003`；证据 `EVD-007`、`EVD-015`、`EVD-018`、`EVD-023`
- 要求：系统 MUST 管理用户提供或已授权素材的来源、商业使用权、版本、适配关系和 AI
  生成标记；来源或权利未知时不得进入可发布状态。
- 验收：每个素材和变体可追溯到来源与权利状态；缺失权利、来源冲突或未经授权的网络
  素材会阻断发布前检查，并给出可修复字段。

## FR-018：生成可评审的素材与文案变体

- 状态：`ACCEPTED`
- 候选阶段：Phase 2–3
- 依赖：`DQ-05`、`DQ-06`、`DQ-08`
- 产品映射：`PF-004`、`PF-021`；证据 `EVD-007`、`EVD-017`、`EVD-023`
- 要求：Codex MUST 能依据已确认的商品事实、受众、版位、品牌限制和素材权利，生成
  待人工评审的文案、视觉方向和单变量测试变体。
- 验收：输出标明输入来源、固定项、受控变量、AI 状态和风险；事实或权利不足时阻断，
  且不得自动搜索、上传、发布素材或保证广告效果。

## FR-019：创建结构化广告草稿和版本

- 状态：`ACCEPTED`
- 候选阶段：Phase 2–3
- 依赖：`DQ-05`、`DQ-06`、`BQ-03`、`BQ-04`
- 产品映射：`PF-005`、`PF-021`；证据 `EVD-008`、`EVD-015`、`EVD-023`
- 要求：系统 MUST 支持 Campaign、Ad Set 和 Ad 的引导式结构化草稿、字段来源、版本和
  变更差异；账户或目标相关字段必须来自实际上下文，不得猜测默认值。
- 验收：缺失必填字段、枚举未确认、素材未就绪或落地页未检查时草稿保持阻断状态；
  每个版本可复查，且离线草稿不得声称已在 Meta 创建。

## FR-020：执行发布前检查与人工发布交接

- 状态：`ACCEPTED`
- 候选阶段：Phase 3
- 依赖：`DQ-06`、`DQ-08`、`BQ-10`
- 产品映射：`PF-006`；证据 `EVD-015`、`EVD-018`、`EVD-023`
- 要求：系统 MUST 对结构、素材权利、落地页、预算与排期、政策风险和人工确认执行分级
  发布前检查，并记录草稿、就绪、人工交接、审核失败及修复状态。
- 验收：阻塞项不能静默绕过；状态必须标明来源和更新时间，MVP 人工发布交接不会被
  表述为系统已发布，审核失败可回链到具体修复项。

## FR-021：管理素材测试计划和结果

- 状态：`ACCEPTED`
- 候选阶段：Phase 2–3
- 依赖：`DQ-05`、`DQ-06`、`BQ-03`–`BQ-08`
- 产品映射：`PF-009`；证据 `EVD-017`、`EVD-018`、`EVD-023`
- 要求：系统 MUST 保存测试假设、唯一受控变量、主要与保护指标、最小数据条件、复查
  时间、停止条件、有效性状态、结论和后续草稿。
- 验收：配置变化、数据量、分配或比较周期不满足有效性条件时结果为 `INCONCLUSIVE`；
  结论引用实际证据，不制造赢家或把相关性表述为因果。

## FR-022：结构化交接 Codex 输出与 Web 对象

- 状态：`ACCEPTED`
- 候选阶段：Phase 2–3
- 依赖：`DQ-06`、`DQ-07`、`DQ-08`
- 产品映射：`PF-010`、`PF-021`；证据 `EVD-019`、`EVD-023`、`EVD-025`
- 要求：Codex 的重要输出 MUST 使用可校验结构，并在用户明确评审后才能保存或关联到
  Web 素材、广告草稿、诊断、测试或变更对象。
- 验收：交接保留输入范围、证据、生成者、时间、状态和 schema 版本；模型输出默认是
  待评审草稿，不能提升权限、伪造实时数据或直接产生 Meta 副作用。

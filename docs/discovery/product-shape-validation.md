# 产品形态验证

## 前置条件

原型工作只有在至少 3 个代表性端到端场景完成定义，且 `DQ-02` 与 `DQ-06` 获得负责人
初步决定后才能开始。当前 3 个场景已由负责人确认，详细验收与三种形态原型均未完成；
不得使用旧功能清单代替产品决定。

## 可比测试输入

三种形态必须共享：

- 同一组完全脱敏的示例数据。
- 从研究证据选出的 2–3 个核心任务。
- 相同的任务目标、信息完整度和安全限制。
- 相同的默认引导流程与可选高级配置，不为不同方案改变能力范围。
- 相同的完成判定与观察字段。

核心任务由负责人确认后登记：

| Task | 来源问题 | 证据 | 状态 |
| --- | --- | --- | --- |
| TASK-01 / SC-01 | DQ-02、DQ-03、DQ-05、DQ-06 | `EVD-010`、`EVD-015` | REVIEWED |
| TASK-02 / SC-02 | DQ-02、DQ-04、DQ-05、DQ-06 | `EVD-010`、`EVD-016` | REVIEWED |
| TASK-03 / SC-03 | DQ-02、DQ-05、DQ-06 | `EVD-010`、`EVD-017` | REVIEWED |

## 已确认的代表性场景

### SC-01：从投放目标到可审核广告草稿

- 输入：商品或服务、投放目标、受众、落地页及已有素材；缺失信息必须显式标记。
- 素材：允许上传、改编或 AI 生成文案与图片变体，并记录来源、版权状态和生成标识。
- 配置：引导模式收集必要配置并解释影响，高级模式可展开完整候选字段。
- 草稿：集中预览素材、文案、目标、受众、预算和时间等结构化信息。
- 检查：以 `BLOCKER`、`WARNING`、`INFO` 区分缺失字段、配置冲突、素材规格、
  版权和 Meta 政策风险；不得承诺一定通过 Meta 审核。
- 交接：保存草稿版本、检查结果和发布清单，用户在产品外手动发布，状态持续显示未发布。
- 完成标准：形成信息完整、风险可见、来源可追踪且明确未发布的广告草稿；任何关键缺失
  或版权或政策风险都不能被静默绕过。
- 后续验证：常用目标、字段、素材规格和政策规则须在 Phase 0 对照 Meta 官方资料确认。

### SC-02：从只读投放数据到诊断与行动建议

- 输入：明确广告账户、对象范围、时间区间、对比基线、更新时间、时区、归因口径和
  指标定义的只读投放数据。
- 看板：按投放目标展示核心指标、趋势和分层结果，并下钻至可用的 Campaign、Ad Set、
  Ad、素材及其他维度。
- 异常：说明异常指标、发生时间、影响范围、比较基线和严重程度。
- 诊断：按置信度排列原因假设，同时展示支持证据、反证、缺失数据和其他可能解释；
  不把相关性直接表述为因果。
- 建议：包含动作、适用对象、预期影响、风险、验证周期和停止条件，并标记尚未执行。
- 异常路径：数据过旧、不完整、样本不足、转化追踪异常或归因延迟时降低置信度或拒绝
  下结论。
- 输出：保存可复查诊断报告，并关联广告、素材和测试记录。
- 完成标准：用户能回答发生了什么、影响哪里、可能为什么、证据是什么、下一步做什么
  以及何时复查，且不会误认为系统已经修改广告。
- 后续验证：MVP 指标、归因、数据可用性和诊断效果须在 Phase 0 及真实数据阶段确认。

### SC-03：从素材变体到测试结论

- 输入：从素材库或广告草稿选择至少 2 个变体，并定义需要验证的假设。
- 变量控制：识别图片、文案、受众、版位等变化，默认建议一次只测试一个主要变量；
  无法公平比较时给出阻断提示。
- 计划：包含主要指标、保护指标、受众与投放条件、预算与周期、最小数据条件、复查时间
  和停止规则。
- 状态：限定为 `准备中`、`数据不足`、`可评估`、`无法判断`、`已结束`，并提示曝光
  或消耗不均、追踪异常和中途配置变化。
- 比较：展示数据范围、指标口径、差异、置信度和干扰因素，不因短期领先直接宣布获胜。
- 建议：限定为 `KEEP`、`STOP`、`ITERATE`、`INCONCLUSIVE`，说明理由、风险和下一轮
  方向；MVP 不自动暂停或调整广告。
- 输出：将结论保存到对应素材，形成可检索的素材表现记录。
- 完成标准：用户能看清假设、控制变量、证据、结论可信度和下一步；数据不足或测试失效
  时必须返回 `INCONCLUSIVE`。
- 后续验证：统计门槛、投放条件和实际增量效果须在 Phase 0 及真实数据阶段确认。

这 3 个场景是产品负责人确认的范围基线，不等同于真实用户任务或可用性验证。
`SC-01`–`SC-03` 已由 `EVD-015`–`EVD-017` 完成负责人场景评审。该结果确认
候选范围、流程、异常和完成标准，不等于真实用户任务完成率或广告效果验证。

## 三种低保真方案

| Prototype | 形态 | 必须表达的交互 | 状态 |
| --- | --- | --- | --- |
| PROTO-A | Codex 对话式 | 任务发起、澄清、结果、证据和下一步 | COMPARISON_BASELINE |
| PROTO-B | Web 工作台式 | 导航、状态、信息层级、操作和反馈 | COMPARISON_BASELINE |
| PROTO-C | Web 工作台 + 内置对话助手 | 对话辅助与可视状态、素材、草稿和数据之间的交接 | OWNER_SELECTED_CANDIDATE |

原型不得连接真实接口、真实账户或未脱敏数据，不得暗示候选写操作已经授权。

## 负责人选择

负责人在比较三种结构的职责与取舍后选择 `PROTO-C`：

- Web 工作台承载素材、广告草稿、测试、投放数据、状态、证据和明确控制。
- 内置助手承载素材生成、配置解释、异常诊断和下一步建议。
- 对话结果必须落入可浏览、可检查的工作台对象，不能只存在于会话历史。
- 选择理由是同时满足端到端状态管理、新手引导、熟练用户高级配置和解释型任务。

纯对话方案不作为主形态，因为大量对象、状态和指标比较容易被会话淹没；纯 Web 方案
不作为主形态，因为创作、解释和开放式诊断会转化为复杂表单。该选择由 `EVD-013`
支持，但在完成下述场景评审前仍是候选结论。

## 已确认的交互基线

- 主导航包含总览、素材、广告草稿、数据分析和素材测试。
- 内置助手自动使用当前页面和已选对象作为上下文。
- 默认使用带术语解释和必要信息收集的引导模式，熟练用户可切换高级模式。
- 素材变体、广告草稿、诊断报告和测试建议必须保存为可浏览、可检查的对象。
- 全局持续显示当前工作区、广告账户、数据时间范围、新鲜度和操作权限。
- `Owner`、`Editor`、`Viewer` 分别承担管理、编辑和只读职责，助手继承当前角色和范围。
- 结果显示来源、输入范围、生成时间、数据口径、置信度和状态；审计区分人工与助手行为。
- MVP 的助手只生成草稿与建议，用户在产品外手动发布广告。

该结构由 `EVD-014`、`EVD-019` 确认；具体字段和页面布局随后续设计继续收敛。

## 终端与失败设计

- MVP 是桌面优先的响应式 Web；移动端支持总览、数据查看、诊断、助手对话、草稿或
  报告审核和轻量修改，复杂素材编辑与高级配置优先使用桌面端。
- 对象使用草稿、需要补充、被阻断、待审核、数据不足、数据过期和失败等可理解状态。
- 生成、同步或分析失败时保留已有输入与草稿，并说明原因、影响范围、能否安全重试和
  下一步。
- 不支持的 Meta 目标、字段或指标不得使用近似值替代，必须显式标记并留待 Phase 0。

该设计由 `EVD-021` 确认。当前只能评估设计对场景步骤的覆盖，不能把该覆盖率表述为
真实用户任务完成率。

## 测试脚本

项目负责人使用 `SC-01`–`SC-03` 评审三个方案，并轮换方案顺序，避免固定顺序偏差。
每个方案记录：

- 核心任务是否完成及需要的提示次数。
- 完成路径、阻塞、误解和放弃点。
- 能否找到来源、口径、数据时间和限制。
- 能否区分建议、审批和真实外部写操作。
- 对结果的信任理由，而非单纯喜好。
- 相比当前替代方案的实际改善或退步。

## 选择门槛

- 至少 3 个代表性场景完成比较，每个场景都覆盖三个方案。
- 选定形态的关键任务完成率不低于 80%。
- 不得出现对数据可信度、权限或广告写操作的关键误解。
- 选择理由必须同时包含任务表现、问题证据、内容适配和限制。
- 没有方案达到门槛时，结论为 `INCONCLUSIVE`，迭代后重测，`DG0` 保持 `PARTIAL`。

偏好排名可以作为辅助信息，但不能覆盖任务失败或安全误解。该评审只验证负责人定义的
场景覆盖，不构成真实用户可用性验证。真实效率提升和广告效果提升不作为当前低保真
评审的通过条件，必须延后到具备真实数据和相应授权的阶段验证。
